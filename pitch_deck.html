HMS 04
THE SOLUTION

HMS is three products.
One semantic foundation.

Each product serves a different consumer. They share the same core, so adding one strengthens the others.

FOUNDATION · PHASE 1

DataPro

The semantic data layer. Turns scattered sources into typed objects with identity, relationships, and provenance. Deterministic runtime. The foundation everything else stands on.

AGENT INTERFACE · PHASE 2

DataMCP

The AI agent surface. Exposes DataPro through the Model Context Protocol so AI agents can ask structured questions about systems — and get reliable, bounded, provenance-tracked answers.

HUMAN INTERFACE · PHASE 3

DataViz

The 2D spatial dashboard. Lets engineers pan, zoom, and explore their entire system as a navigable map — building intuition the way humans actually think about space.

HMS 05
USER STORY · A NIGHT ON CALL

One question. Two worlds.

"Why is checkout-pricing failing?"

3:14 AM
WITHOUT HMS
Page fires. Open Datadog. Switch to Grafana. Open the K8s dashboard, then the deploy log, then the monorepo. Search Slack. Ping the owner — who's asleep. Check the incident channel from last week. Skim a runbook that's two years out of date. Cross-reference three timestamps in three different timezones. The fix turns out to be a one-line config flag from a deploy 8 hours earlier.
Time to resolve: 47 minutes
3:14 AM
WITH HMS
Page fires. The on-call AI copilot calls DataMCP for the checkout-pricing object. DataPro assembles a single resolved view: current status, last 3 deployments, dependencies, recent error metrics, and the engineer who shipped the change. The copilot proposes the rollback. The human reviews it in DataViz and clicks approve.
Time to resolve: 90 seconds

HMS 07
UNDER THE HOOD · DATAPRO

What a DataPro query actually looks like.

Query
// One question, no SQL, no PromQL { "from": "AppInstance", "where": { "name": "checkout-pricing" }, "include": { "host": true, "owner": true, "recent_deployments": { "within": "24h" }, "metrics": { "names": ["error_rate", "latency_p99"], "within": "1h" } } }
Response — assembled from 4 backends
{ "type": "AppInstance", "id": "prod/checkout-pricing", "status": "degraded", // from K8s "owner": "payments-team", // from Postgres "host": { "id": "h-918", "region": "us-east-1" }, "recent_deployments": [ { "sha": "a3f1e9", "at": "2026-04-28T19:02Z", "author": "jane@..." } // from Git ], "metrics": { // from VictoriaMetrics "error_rate": 0.12, "latency_p99_ms": 2840 }, "_provenance": { "all_fields": "ok" } }

The hard part isn't the syntax — it's resolving identity across sources, planning the joins via a link store, enforcing query safety contracts, and assembling a provenance-tracked result. That's DataPro. DataMCP exposes this same shape over MCP for AI agents; DataViz renders it spatially for humans.
